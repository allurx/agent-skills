# 维护验证与记录

用于全局协作指令的验证方案、实质变更实施及相关后续效果评估。按本次目标、实际行为变化和风险选择验证；本资料不要求每次审查读取全部历史、执行固定全量场景或修改生效配置。

## 验证目标与范围

以减少遗漏、越界、冲突和无价值改动，提高任务质量与协作效率为目标，同时考虑理解、执行、验证和长期维护成本。不以条款数量、文字长度或结构整齐代替实际收益。

授权、任务范围、工作区保护、验证或交付等方面的关键行为要求发生变化时，执行受影响的代表性场景，检查实际动作、产物和声明。措辞澄清检查代表性场景的解释；纯措辞或结构整理不默认重跑全部行为场景。内容迁入 Skill 时，验证相关任务能够发现并读取承接资料，原有适用条件和约束仍可到达。

采用候选前明确可观察的验收标准，将触发证据、问题判断、候选变更及理由与相应案例关联。分别判断干预机制是否执行、原问题是否改善，以及是否引入退步；增加了一次复核或正确复述规则，只能证明相应动作发生，不能代替改善证据。

涉及意图识别、授权或任务延续时，使用相关的多轮状态转换，检查实施中的讨论、明确变更、撤回及继续执行如何改变实际动作。涉及并行工作时，还应检查相关协作者是否停止旧方案写入、主 Agent 是否回读最终状态，以及无关或仍获授权的工作是否保留；不以单轮回答代替这些场景，也不为无关变更固定执行全部流程。

## 比较条件与证据

涉及行为改进时，优先使用真实任务形成的代表性案例，在可比条件下比较原版和候选版。记录指令及相关依赖的版本、模型、环境和实际差异；条件不可比时说明限制，不声称已证明提升。

结合实际动作、产物及用户反馈判断结果，并检查遗漏、越界、误报、无价值改动与相关成本。验证写入或撤回行为时，在获准的隔离环境中检查实际 diff、文件或目标状态，并与相关协作者的动作对应；只回答应当如何做不算实际执行。功能结果、静态视觉和连续操作过程按目标分别验收，不相互替代。结构检查通过、模型自评或单次成功，不能独立证明持续改善；文本回答或操作计划也不能证明真实写入、加载或外部状态已经完成。

验证主动发现问题的能力时，只提供完成任务所需的请求和原始材料，不提示待发现的问题、预期答案或修法。配套反例检查合理实现是否被误改、必要机制是否被误删；经提示后修正或服从提示，不能证明自主发现能力。

用于捕获已知遗漏或回归的检查，应在可控条件下确认能使相应旧错误实现或已知错误样本失败，同时让正确实现通过，避免前后都通过却宣称缺陷已被覆盖。按实际风险选择临时验证或长期测试，不为验证候选强制增加永久测试；无法运行旧版本时，说明替代证据及其限制。

## 记录、续接与纠正

优先续接已有记录，按内容归属和有效授权保存，不把案例正文放进全局指令或 Skill 本体。记录关联以下内容，以支持复核和后续比较：

- 触发证据、问题判断、候选变更及理由，对应的验收标准与案例。
- 验证结果、实际覆盖和缺口，以及采纳或未采纳的依据。
- 维护源及相关依赖版本、生效范围和后续效果；行为比较同时保留所用模型、环境及不可比条件。
- 当前状态：候选已审阅、维护源已修改、已部署、已加载与行为已验证分别说明，不相互替代。

记录本身不扩大操作授权。后续出现相关新证据时，重新评估原结论并说明原因；发现退步时，在授权范围内修正或撤销相关改动，保留原因，不覆盖后来无关的修改。无法完成验证或纠正时，说明未解决事项、具体原因和下一步。
