# 全局协作指令提炼与复核

审查现有全局协作指令，从历史会话中提炼有长期复用价值的要求，或在明确授权下实施已经审阅的候选修改。审查默认交付有证据的候选报告；实施按已审阅方案完成修改与相关验证。

## 安装

无需构建，安装源为完整 `skills/global-instruction-review/` 目录。按[仓库安装与更新说明](https://github.com/allurx/agent-skills#安装)选择目标位置，并保留整个目录。

## 使用

```text
使用 $global-instruction-review 审查这份全局协作指令，说明需要保留、合并、删除或迁移的条款及依据，先交付候选方案，不修改文件。
```

可按任务使用三个入口，具体范围见 [任务选择](SKILL.md#按任务选择范围)：

- **直接审查当前条款**：提供原文、文件或可核实版本。只在相关依据需要追溯时读取历史，不自动扫描全部会话。
- **从历史协作提炼要求**：说明来源、时间范围和报告时区；如有上次提炼记录，可一并提供。Skill 会核实实际覆盖并说明无法确认或读取的部分。时区选择见 [审查范围与时区规则](SKILL.md#确定审查范围)。
- **实施已审阅的候选**：提供或指明已审阅方案，并明确允许修改的对象。Skill 会核对当前文件与方案，保留未列入变更的要求，完成相关验证；不自动重新开展整轮历史提炼。

审查报告先列最终候选，再逐项给出来源、当前条款、完整候选文本、收益、代价和验证方式，并说明主要未采纳项及实际覆盖与缺口。现有规则已经足够或证据不足时，可以没有候选修改；已识别的执行问题仍需交代诊断依据、具体改进、验收方式和未解决部分。实施交付说明实际修改、与方案的对应关系、验证结果和剩余限制。

维护验证按实际变化选择场景，方法和记录要求见 [维护验证与记录](references/maintenance-validation.md)。纯措辞或结构整理不默认运行全部行为场景；结构检查或单次成功不能证明持续改善。

历史访问取决于宿主提供的工具和材料，Skill 本身不提供额外访问能力。单纯查询历史、讨论提示词或整理已有指令层级不属于本 Skill 的提炼任务；结构整理可使用 `instruction-structurer`，无需将它作为本 Skill 的运行依赖。

候选报告及方案获认可不自动授权修改维护源、同步生效文件、保存记录或执行 Git 操作；另有明确授权时按其范围处理，无需重复确认。此 Skill 不自动定时运行。完整判断与实施方法见 [SKILL.md](SKILL.md)。
