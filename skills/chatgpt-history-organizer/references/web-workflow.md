# ChatGPT 网页批量核验参考

批量枚举时读取分页规则；通过内部接口读取正文或执行核验时再读取相关部分。下列请求形状来自一次成功任务的观察，不是公开稳定 API；ChatGPT 更新后可能失效。

## 安全边界

- 先通过正常网页登录，并使用当前页面同源会话。
- 从当前网页实际网络请求确认 URL、HTTP 方法、请求体和响应字段；不要凭本页盲写。
- 接口访问不扩大授权。只读审计不能执行改名或移动；移动仍须通过项目共享和聊天资格检查，不能绕过界面的不支持状态。
- 不打印、复制、持久化或回传 `authorization`、Cookie、会话令牌及其他凭据。
- 用稳定聊天 ID 跟踪进度。每次写入后重新 GET 验证，不依据 HTTP 200 单独判定成功。

## 分页与目录一致性

全局聊天目录曾使用：

```text
GET /backend-api/conversations?offset={offset}&limit=100&order=updated
```

`order=updated` 是可变排序：读取第一页后，旧聊天更新并移到前面，会被后续 offset 跳过；按 ID 去重只能消除重复，不能恢复漏项。响应中的 `total` 曾与实际可分页数量不一致，不能只依靠 `total`、某页零新 ID 或侧栏暂时为空证明全量。

- 先观察分页契约、过滤条件和列表覆盖范围。仅在已核验支持时使用稳定排序、快照或 cursor；cursor 本身不保证跨页快照一致性。
- 每轮扫描期间暂停本轮写操作，按已确认的分页规则读取到终点，保留原始页计数并按 ID 合并。中途报错、重复 cursor、响应截断或未到终点就持续无进展，均记为不完整；不把异常当作空页。
- 只有 offset 可用且缺少快照保证时，完整扫描后从头复扫，比较连续两轮的 ID 集合及标题、项目归属和可用更新时间/版本。最多执行三轮完整扫描；仍不一致或扫描失败则停止批量写入，报告目录不稳定和已覆盖范围。连续两轮一致只是观察期间稳定的证据，不能承诺并发修改下绝对无漏。
- 建立目标集合后，固定每个 ID 的授权动作和预期结果。写入结束后按同样规则复核目录，同时逐 ID 核验目标；出现缺失、未知归属或并发变化时保留差异，不用新的计数覆盖原始目标。
- 新增 ID 默认属于本轮范围外；报告其数量和对侧栏的影响，不自动加入写入队列。

项目内聊天目录曾使用：

```text
GET /backend-api/gizmos/{project_id}/conversations?cursor={cursor}
```

按已确认的响应字段翻页，直至没有下一页；同样检查 cursor 重复、扫描失败与并发变化。仅列完项目内聊天不能证明覆盖了未归类历史，需核对全局目录与项目目录的实际覆盖关系。

## 正文覆盖与有效分支

单条聊天详情曾使用：

```text
GET /backend-api/conversation/{conversation_id}?include_has_versions=true&num_turns=100
```

`num_turns` 的可用上限曾为 100；单次成功响应不证明取得整条对话。先观察当前网页加载较早消息和切换分支的真实行为，确认详情响应的覆盖边界及节点字段。

- 若已确认响应使用 `current_node`、`mapping` 及 `parent` 表示当前分支，从当前节点沿父链回溯并按对话顺序读取，再筛选真实用户消息，必要时结合回复理解上下文。不能遍历整个 `mapping` 后把已弃用分支混在一起；也不能假定对象枚举顺序就是对话顺序。
- 检查父节点缺失、未回溯至已验证的起点、分页/截断标记，以及页面是否还能加载更早消息。达到 100 轮只能提示检查边界，不能单凭数量断言完整或截断。
- 按实际观察到的分页方式或网页操作补读较早内容；判断长期主题须覆盖起始意图和主要阶段，不能把最近一段当成全部历史。全量及既有结果复核也须审查已归类记录的内容与项目是否匹配。
- 无法确定当前分支、补齐必要阶段或读取决定主题的附件时，将该 ID 标为证据不足；停止依赖这些内容的改名和移动，并记录原因。不猜测未观察到的参数，不根据标题或其他分支替代缺失证据。

## 已观察到的写请求

标题更新曾使用：

```text
POST /backend-api/conversation/id/{conversation_id}/rename
Content-Type: application/json

{"title":"新的准确标题"}
```

项目移动曾使用：

```text
PATCH /backend-api/conversation/{conversation_id}
Content-Type: application/json

{"gizmo_id":"目标项目 ID"}
```

仅发送 `conversation_template_id` 曾返回成功但实际项目字段未更新。应先确认当前详情中 `gizmo_id`、`conversation_template_id` 等字段的实际含义，并与真实项目目录和页面归属交叉核对；自定义 GPT 标识或其他非空 ID 不能当成项目 ID。写后核对目标项目的准确 ID 和页面结果，不能相信成功响应本身。

写前重新读取聊天和目标项目；已有变化时重评内容、归属与授权。区分移动不支持、资格尚不确定、限流和写入失败：不支持的记录不发送 PATCH，未知资格先调查，失败按入口的有限恢复规则处理。改名资格与移动资格分别记录。

## 按范围验收

- 本轮目标 ID 唯一，授权动作保持在原定范围内；扫描证据及其一致性限制明确。
- 审核覆盖按 ID 记录；全量及既有结果复核包括已归类记录的标题与归属语义，不能用 ID 非空替代内容审核。
- 本轮每个改名 ID 的当前标题与预期完全一致。
- 本轮每个移动 ID 的当前项目与预期的真实项目完全一致，目标的共享状态仍符合授权。
- 分别统计目标 ID 数、授权改名/移动数与各自成功数，以及可移动目标未归类、不可移动、资格未知、内容未验证和范围外新增数量；这些类别按各自维度计数，不混为一项“已完成”。
- 刷新页面核对本轮目标。仅全量归组才验收可移动且获移动授权的目标未归类数为零；不可移动记录和范围外记录可以继续出现在侧栏，不能为清空它们扩大权限或绕过限制。

只读审计按证据覆盖和问题报告验收；证据缺口必须保留，不能表述为已通过。若数据核验与界面显示矛盾，应刷新并重新读取一次；仍矛盾时报告差异，不宣布相关写入或全量整理完成。
