# ChatGPT 聊天记录整理

根据真实聊天内容完成用户要求的审计、改名或项目整理。完成标准由本轮授权动作和目标范围决定，不把局部任务扩大为全账号清零。

## 授权与范围

- 读取和审计可以直接进行；创建项目、重命名和移动聊天分别需要用户授权。已有明确授权时直接执行，不重复确认。
- 不因整理授权删除、归档、分享、发送聊天或更改正文。移入共享项目本身会让项目成员看到聊天，不能视为纯目录调整。
- 先核对当前账号、工作区及 ChatGPT 网页聊天入口，不操作 Codex 本地任务或 ChatGPT 工作任务。
- 默认仅使用已核验为私有的项目；共享状态未知时不移动。只有用户明确授权向已核验的目标项目成员共享对应聊天时，才能选用共享项目。移动前核验项目身份、共享状态及会继承的指令和上下文；说明会实质改变后续使用的重要影响。
- 复用主题合适的私有项目；仅在现有项目无法容纳稳定主题且创建已获授权时新建，避免一条聊天一个项目。

按请求选择模式，记录目标范围和允许动作；未获授权的操作只给出建议：

| 请求模式 | 执行与验收范围 |
| --- | --- |
| 审计、评估、复核 | 只读；报告范围内的标题、归属及证据问题，不以修复或清零作为审计完成条件。 |
| 仅改名 | 读取指定聊天并核验已授权的新标题；不移动聊天或创建项目。 |
| 局部整理 | 仅处理指定 ID、项目或过滤条件内的聊天，按已授权动作验收。 |
| 全量整理 | 建立完整目录，审查全部目标聊天的标题和归属，执行已授权的改名与移动；不可移动记录单列。 |

默认以目录建立时确定的目标 ID 集合为本轮范围，临时及归档聊天不纳入，除非用户明确指定。执行中新出现的聊天作为范围外差异报告，不自动追加写操作。过滤条件不明确且会影响范围时先澄清。

## 工作流

1. 获取目标目录和项目身份。指定 ID 的任务可直接读取；全量或按条件筛选的任务必须覆盖相关列表全部分页，按稳定 ID 去重。不能把当前视口、搜索结果或一次分页结束当作完整性证明；批量枚举时读取 [分页一致性规则](references/web-workflow.md#分页与目录一致性)。
2. 为每个目标记录稳定 ID、当前标题、已核验的项目归属、授权动作、移动资格及证据状态。项目归属须对应真实项目，不能把任意非空 `gizmo_id` 当成项目。按当前产品能力区分可移动、不可移动和资格未知；GPT 创建的聊天等不支持移动的记录单列，不尝试内部接口绕过限制。不可移动不代表不能审计或改名，分别判断每项动作。
3. 按模式读取足以判断主题的真实内容。全量整理及既有结果复核必须包含已归类聊天的标题和归属语义审查，不能仅检查项目 ID 非空。跨主题聊天按最初或占主导的长期主题判断，不因末尾偶发问题迁移。
4. 确认正文未因长对话截断且属于当前有效分支；存在早期消息缺失、分支不明或只有附件引用等证据缺口时先补读。无法补足则记录未验证，停止该记录依赖内容的改名和移动，不根据旧标题猜测。使用内部详情接口时读取 [正文覆盖规则](references/web-workflow.md#正文覆盖与有效分支)。
5. 根据实际内容提出标题和归属；仅执行授权动作。对同名聊天逐条比较，主题或深度不同则用限定词区分；内容相同也保留各自记录，不删除或合并。
6. 分批写入并按 ID 记录结果。写前复读目标；若标题、项目、内容版本或目标项目共享状态已改变，重新评估，不覆盖并发修改。写后重新读取核对，不以请求成功作为完成证据。
7. 按模式验收：只读任务报告审核覆盖和发现；写入任务核对每个已授权操作的实际结果，并刷新页面核对相应标题或归属。全量整理还须重扫目录、核对目标集合和语义审核覆盖，分别报告可移动目标未归类数、不可移动数及资格未知数。只有全账号实际无残留时才称侧栏清零；局部任务或存在不可移动记录时不要求侧栏为空。
8. 证据不足、限流、目录不稳定或数据与界面矛盾时，报告已验证结果和未完成范围，不宣布全量整理完成。

## 标题原则

- 根据真实内容命名，不根据旧标题猜测内容。
- 对含糊、失真、内容不符、截断、错别字、残留字符及同名标题优先复核；不要仅因出现“建议”“解析”等词机械改名。
- 保留用户能识别的技术名、产品名、类名、方法名和地域等关键词。
- 避免“新聊天”“代码”“优化建议”“问题分析”这类脱离上下文就无法检索的名称。
- 不把整段提问复制为标题，也不加入未经聊天内容支持的结论。
- 对包含医疗、财务或个人经历的聊天，在准确性和侧栏隐私之间取平衡；没有必要时不暴露过多敏感细节。

## 限流与恢复

- 从小批量开始，依据当前响应和界面反馈调整，不把历史次数或固定冷却时长当作产品限额。
- 发生限流即停止对应读写，优先遵循服务给出的重试时间；无明确时间时保守等待。一次冷却后仅做一次探测，仍受限则保留已核验进度并报告未完成范围，结束本轮，不无限重试。
- 恢复时复读目标状态和授权范围，仅继续尚未完成的 ID；不能为降低读取量跳过本轮要求的语义审核。
- 若 UI 行为无反馈，先检查状态和错误，不盲目重复。只有在当前环境允许且已确认请求语义时，才使用同源已登录会话的接口路径。
- 任何会话凭据只保留在运行时，绝不输出、写文件或记录到 Skill 结果中。

需要通过 ChatGPT 网页内部接口提高批量核验效率时，读取 [references/web-workflow.md](references/web-workflow.md)。接口可能变化，必须先观察当前网页请求并验证字段语义。移动资格、项目共享和上下文行为也应按当前 [OpenAI 项目说明](https://help.openai.com/en/articles/10169521) 与实际界面核验。

## 交付

报告模式、目标范围及唯一 ID 数、实际内容审核数、授权的改名/移动数及各自成功数、项目数量、可移动目标未归类数、不可移动及资格未知数、范围外新增差异、验证方式和未验证项。只读审计可以完成并报告问题；写入或全量审核尚有缺口时明确标为部分完成，不把局部成功外推为全量完成。
