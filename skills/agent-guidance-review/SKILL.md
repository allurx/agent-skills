# 指令与 Skill 评估

用户只输入 `$agent-guidance-review` 时，使用当前会话的模型完成一次只读评估，并在对话中交付一份报告。用户无需提供路径、旧模型或待查问题。评估关注这些指令能否帮助用户完成实际任务，以及哪些地方引起误触发、遗漏、越权或重复工作。

## 确定本轮评估对象

- 从本 Skill 的实际加载路径解析目录链接，优先定位本地 `allurx/agent-skills` 源码仓库。检查同一工作区中的 `allurx/codex-dotfiles`。复制安装时，可从当前工作区、已知项目位置或其他个人 Skill 的源码链接定位两个仓库。通过 Git 远端、仓库维护说明等确认身份，按需分别定位两个来源。
- 全局指令取自 `codex-dotfiles/codex/AGENTS.md`。核对本机 Codex 主目录实际选用的全局文件和覆盖关系。Skill 清单取自 `agent-skills/skills/` 下各包的 `SKILL.md`，包括工作区中尚未提交的新包和本入口。用目录、维护源与实际运行版本区分自维护包、第三方安装项和构建产物。调用目录只影响查找起点。
- 本地维护源不可读时，可读取对应公开仓库同一固定提交的目录与原文，记录使用的版本及本地覆盖缺口。某个来源缺失时先评估可取得的部分。记录模型、维护源版本及影响判断的本地差异；未暴露的模型版本或安装状态标为未知。

## 先确定用什么判断对错

从用户明确表达的目标、偏好、授权和可观察的任务结果建立判断标准。有争议的旧条款、Skill、校准答案和旧报告都是待检验的材料。区分用户亲自确认的要求、旧模型提出的做法和来源暂时不明的约定。模型更新可以使某种做法值得重评，采纳或删除它仍需说明实际影响。

换模型时，由入口自行安排两项工作。用当前配置观察日常任务的真实表现，同时按[独立复核方法](references/independent-review.md)安排同一目标模型独立判断旧稿。新模型应有机会发现旧报告未提及的问题，也可确认旧做法仍有价值。将两个结果分别形成后再比较。使用条件受限时，完成有依据的部分并注明缺口，用户仍只需调用一次。

## 检查指令对真实任务的影响

通读全局条款和每个 Skill 的入口，结合用途核对触发条件、实际工作流、交付和权限。按需检查脚本、参考资料或产物。日常配置下专项复核全局要求时，可复用 `global-instruction-review` 的方法，同时检查它是否预设了结论。留意各项指令配合使用时出现的冲突、额外步骤，以及撤掉旧提醒后可能失去的用户约束。

选择能区分正确与错误行为的小组任务，优先使用已有的真实案例、失败记录及仍适用的验证。用自然语言测试应该触发和容易误触发的相邻请求，涉及执行时检查实际工具动作、文件差异或成品。使用只读材料或隔离样本，保留操作授权边界。每项都给出有依据的判断，深入试验优先覆盖受模型变化影响、高风险或证据不足的部分。

有可比的旧模型结果或历史产物时，对齐任务输入、工具、权限和推理设置；对关键或波动的结果按需复测。判断旧做法是否仍有价值时，优先让同一新模型在相同任务下比较原配置和仅改变该做法的候选。既看预期收益，也看它原本保护的行为。缺少旧模型基线时，仍可评估当前做法的价值，历史退步的原因则保持未定。

## 评估入口自身

将本文件、入口描述和实际使用的配套资料列为一个受评对象。用本轮实际读取清单、工具动作及报告核对入口是否找全对象、是否越过只读范围，以及证据能否支持结论。评估本入口时直接核对本轮执行，无需递归启动完整评估。

换模型或首次建立基线时，把[校准样本](references/calibration-cases.md)单独交给执行者，只给出评估目标和原始材料。收到结果后，对照[预定判据](references/calibration-key.md)和材料中的实际动作。判据与用户目标相冲突时，记录分歧并重评判据。日常复查可复用同模型、同版本的有效记录。盲测只说明答案在评分前未提供，启动环境是否独立另行核对。

## 交付一份评估报告

先回答这次值得改什么、为什么，允许全部保留。按对象交代依据，区分静态核对、日常配置的实际表现和独立复核的结果。写明独立复核使用的模型、可验证的隔离范围和缺口。两种判断有分歧时，以用户目标和可复查的任务结果解释取舍；证据不足的建议标为待验证。给出重要调整的落点、收益和验证办法。裸调用的交付到报告为止。
