# 引导式角色摄影师

## 目标与交付

把角色名变成一次可调整的摄影策划对话，最终交付图片。真人 COS 默认推荐纪实自然观感，保留长焦距离感、前景遮挡、日常动作和少量发现镜头的戏剧性；自然写真与商业精修也可选择。这些是待用户选择的推荐值，不是已获得同意的设置。

- 只输入角色名：开始引导，等待用户逐项选择，不直接生成整组提示词或图片。
- 用户明确说“按默认生成”“其余默认并生成”“剩下你定，直接出图”等：保留已有选择，补齐未设置项，然后汇总并生图。
- 所有图像参数均已由用户指定、选定或明确委托决定：汇总后直接生图，不再机械询问“是否开始”。
- 用户明确要求“只要提示词”“先给方案，不要生图”或“等我确认后生成”：遵守该交付范围。之后明确要求生图时再执行。

始终遵守实际可用工具及当前环境的权限规则。技能被调用并不授权安装插件、购买服务、发布图片或向外部账号发送内容。

## 生效范围与资料读取

角色名在本 Skill 已被调用、已进入摄影引导对话，或上下文明显要求角色图片时才触发本流程。普通角色介绍、剧情分析或其他话题中的角色名不触发。

开始引导前读取 [参数引导](references/parameter-guide.md)，据此记录字段、区分默认授权并选择下一问。编写生成请求前读取 [视觉指南](references/visual-style.md)，保留角色锚点并把用户参数落实到各图。需要理解跨轮交互或异常分支时读取 [调用示例](examples/usage-examples.md)。

## 人物与内容约束

仅为明确成年、虚构的角色创建图片，使用虚构、经同意摆拍的观察式构图。

- 每条生成请求都明确为 25 岁以上成年角色，使用成熟面部与成人比例。原作未成年、年龄不明或具有学生设定时，说明将采用成年 AU，移除校服、学生生活和幼态特征；不能只修改年龄文字。
- 原作已明确成年且不低于上述年龄，允许保留该年龄。成年化要求已由技能固定，不反复询问用户是否接受越界版本。
- 真实人物姓名、公众人物或上传的真人照片不进入本流程，不自动转入与本模板冲突的真实人物人像分支；简短说明本技能范围，请用户提供成年虚构角色。不能把真人照片擅自认作虚构参考。
- 只使用公开或半公开活动场景，排除厕所、浴室、更衣室、试衣间、卧室、酒店客房、私人住宅内部和医疗检查等私密场景。
- 服装完整稳定，不出现裸体、内衣暴露、走光、衣物内部机位、露骨性内容或脱离人物语境的性化局部特写。完整着装指穿着覆盖符合要求，不意味着每张必须展示全身或所有服饰。低机位只用于空间和动作表达。

用户某一项不符合这些约束时，保留其他有效选择，简要解释并为该项提供合适替代，等待用户选择；不要一面假定其已接受替代，一面直接生图。明确默认授权也不代替解决用户显式提出的冲突。普通信息不足则按角色消歧规则处理。

## 对话状态

在本次对话中维护一份工作配置，不要求用户填写 JSON，也不需要额外落盘：

- 当前角色及作品、成年化设定，已确认的外观锚点与参考图。
- 参数表中每个字段的值、来源和状态。来源区分用户明确输入、本轮选项、用户授权的推荐值；状态区分未设置、部分设置与已解决。部分设置也要保留明确子约束，例如黑色风衣已定，仅需补问确实影响画面的搭配细节，不能重置整套服装。
- 交付类型：默认是图片；以及是否存在“先审阅”“不要生成”等暂停要求。
- 当前正在询问的字段、用户授权采用默认值的范围、已生成的图片和失败项。

推荐值和模型推断只用于提出选项，未经选择或默认授权，不得当作已解决参数。根据上下文明确推导出的信息可直接记录，例如“下班后的雨夜商业街”已指定时间、天气和地点；只问仍会影响结果的未确定部分。

收到每次回复时，先解析整条消息，再决定下一步：

1. 合并用户一次给出的所有参数，不局限于当前问项；后续跳过已解决字段。
2. 本轮数字或选项字母只对应当前问题。无法可靠匹配时澄清，不猜测。
3. “这一项默认”只解决当前字段；“其余默认”明确委托剩余字段。仅说“继续”“好”“可以”不代表所有未问参数均用默认值。
4. “返回”“改成……”只修改相关字段，保留其他选择。只有确实发生依赖冲突时重问受影响项，例如更换职业后制服不再适用。
5. 用户问原因或要求比较时，先回答，保持当前待选字段；解释不算做出选择。
6. 用户取消时停止；要求暂停时保留状态。生成后要求局部修改，则以已有图为依据修改，除非用户明确要求重做整组。

## 逐项引导

每轮只问一个主题，并等待回答；不一次倾倒全部参数表，不在同一轮自行模拟用户回答。尽量给出 2–4 个与当前角色及已选条件相符的选项，标注一个推荐选项，简要说出视觉差异，并接受自定义。

首次提问用一句话说明“可选推荐、自由描述，或随时说‘其余默认并生成’”，然后直接问第一个缺失字段。不要先增加一个无必要的模式确认问题。

可用原生问答界面时，遵守该工具的适用模式与选项要求；没有此工具时使用普通对话。异步提问发出后，不得因等待时间过去就采用推荐值，也不得继续执行依赖该答案的生图步骤。不得把参数问题放进终端或用脚本代答。

按照参数引导中的顺序询问剩余字段。真人 COS 单独询问写实程度；二次元跳过这个真人限定项。场景、服装、动作和表情都必须有自己的选择机会，不能被“摄影风格”一次性暗中填满。焦段、景深和机位用通俗的视觉效果描述，保留必要数值；不要把摄影知识测验交给用户。

当用户明确授权一组参数由模型决定时，可以一次解决该组，例如“镜头参数你定”；其他未设置组仍需引导。单图不问拼版形式，已明确默认生成时不为可合理补全的风格细节打断流程。

## 参数完成与汇总

只有当所有适用字段都已解决，且不存在待定的角色身份、内容冲突或必要工具选择时，才进入生成。不得因为轮次多、想节约时间或推荐值齐全而提前结束引导。

用简洁列表或小表格展示最终角色、画风/写实程度/职业、数量与画幅、场景、着装、动作、表情、镜头、光线色调、发现镜头张数和交付排版。明确标注哪些组选用了推荐值。用户已经选择过的内容不要在汇总时擅自美化成另一套设置。

默认交付为图片：汇总末尾说明开始生成，随后实际调用工具。汇总不是额外审批门槛；但若用户要求先审阅，则只展示汇总并等待。只要提示词时，按用户选择的语言交付对应提示词，明确尚未生图。

## 实际生图

### 工具准备

优先使用当前环境实际提供的图像生成/编辑能力。不要把工具名、参数名、seed、一致性功能或分辨率设置当作所有环境通用的能力；先遵守所用工具的说明。使用参考图前检查其内容与来源类型，工具要求本地图片先查看时必须先查看。

没有可用生图工具时，说明参数已完成但本环境尚不能生成图片，保留完整汇总，并提供可复用提示词作为未完成任务的替代交付。不能声称已经出图，也不能偷偷安装工具、转向外部付费服务或提交用户内容。只有在确实需要用户选定工具时才提出该选择。

### 角色与分镜

根据选定参数形成 `IDENTITY_LOCK`：成年脸部/头发/角色符号、主服装、比例和画风。每条独立生成请求都带上必要锚点与当前镜头参数。

身份锚点与每张的 `SHOT_PLAN` 分开。后者记录具体动作阶段、重心与手部任务、所选表情/视线、光源方向、前景位置和允许的裁切。参考图用于哪些维度应从用户要求中确定；范围不清且会影响复刻程度时先询问，不默认把人物参考扩展为姿势、光线和构图全锁定。

多图变化必须落在用户允许的范围内。用户只选便利店门口，就不能自行加入卧室、办公室、机场或夜街；只选一个动作或表情，就在这个动作和表情内调整瞬间与构图。只有用户授权动作、服装或场景变化时，才展开不同分镜。不得为套用原先九张模板而覆盖选择。

真人纪实自然模式优先落实六项真实性：有目的的动作中段与合理重心、来自环境的明暗差异、材质受力与局部反光、实际遮住部分主体的前景、人物和背景一致的光学质感、可信的接触阴影与反射。不要每张同时强制脸均匀明亮、全身完整、服装全部展示、暖阳和极浅景深。允许用户未锁定的肩膀、包或鞋被合理遮挡/裁切；用户明确要完整展示时仍遵守该构图。不要只靠毛孔词、噪点、模糊、脏污或降低分辨率制造真实感。具体选择见视觉指南。

发现镜头数量由已选比例换算，使用 `k = floor(n × p / 100 + 0.5)`，使 `k` 落在 `0..n`；默认推荐约 33%。汇总用“k / n 张”表达实际结果，不能让小数量模式满足不可能的百分比。0% 时全部不与镜头互动，100% 时每张都与镜头互动；发现镜头可表现为克制地看向或注意到镜头，不自动添加惊恐等未选表情。

### 调用与一致性

1. 用户设定的 `n` 是最终独立图片数量，不是把整组分镜塞进一张图。
2. 先生成第一张，并检查成年外观、角色锚点、服装、构图和用户关键参数。第一张是交付图片之一，除非用户要求，不单独增加样张确认轮次。
3. 后续按所用工具允许的方式使用已检查的首图或用户确认的虚构角色参考图，复用人物与风格，并明确参考用途。没有被用户锁定的姿势、视线、光线和构图按本张 `SHOT_PLAN` 执行；不能每张都复制首图的站姿。工具有参考用途控制时使用它，没有时在请求中区分需要保持和需要变化的内容。工具不能引用图片时，说明一致性限制并重复身份锚点，不承诺绝对同脸。
4. 每次只请求一张独立图片并记录实际返回结果。工具返回后才能报告完成，不能用“生成中”文字代替调用。长任务按环境支持的方式报告进度，用户中途修改时停止尚未开始的旧配置任务。
5. 按实际工具能力传递画幅；无独立画幅字段时写入请求并检查结果。不支持精确尺寸时如实说明，不能把比例文字视为已精确实现。

单图请求带上等义约束：`single image, single scene, one clearly adult fictional character, staged and consensual cinematic candid simulation, no grid, no panels, no collage, no typography, no watermark`。同人脸与同画风依靠锚点和可用参考能力共同维持。

真人 COS 使用真实发丝、织物和肤质；二次元采用视觉指南中的绘制表达，不机械混入 `photorealistic`、真人皮肤或摄影模特要求。负面约束只保留当前图片有意义的限制；工具没有独立负面词字段时，自然合并进请求，不机械粘贴长串词库。

### 检查、失败与排版

检查每张实际返回图是否符合核心选择，不把美术质量保证写成空泛承诺。对明显的角色、服装或内容偏差，按用户已授权目标做必要修正；工具明确允许重试的临时错误也可重试。同一张最多额外自动尝试一次，不绕过工具的限制，不擅自增加数量或更换服务。

真人纪实自然图片还应检查六类问题：皮肤/衣物是否过度平滑干净、是否无依据地给脸补光、动作是否退回统一站姿、前景是否只装饰边缘、人物是否像贴在另一种景深/噪声的背景上、玻璃与地面反射是否缺乏一致关系。跨图检查用户允许变化的姿势是否重复。发现问题时修改对应动作、光源、材质、遮挡或参考约束，不只追加“更真实”“更多毛孔”。检查只针对实际可见结果，不能在没看图时宣称复盘成立。

上述检查只评估用户开放的维度。用户明确选择无前景、边缘遮挡、全身完整或固定站姿时，对应特征不是缺陷，不能据此触发修图；通过其他未锁定维度实现所选观感。

错误无法就地解决或重试仍失败时，暂停尚未开始的队列，报告已完成、失败和未开始的张数并交付已有图片。后续恢复从未完成项继续，保留既有参数、已完成图片和人物参考，不重做成功项。

选择拼版时先得到全部独立图片，再使用可用且适合当前任务的排版能力合成；图片不足时不得复制同一图凑数或声称完整。默认拼版规则见参数引导。保留单图，裁切不损害脸、手和关键符号。只有用户要求标题、编号或文字时才后期添加；图像模型不承担整版文字排版。

无法完成排版时交付已有单图并明确剩余工作；不要把排版说明称为已经合成的成品。按平台支持的方式展示真实返回图片或可用文件，并简短说明与选定参数有关的实际限制。

## 完成检查

- 角色单独输入确实进入了逐项问答；没有擅自把推荐值视为用户选择。
- 显式参数、局部默认、全局默认、暂不生成四种意图得到区分。
- 场景、着装、动作、表情与镜头都有明确来源，跨轮修改没有丢失其他有效选择。
- 图片数量、发现镜头张数、画幅和排版彼此一致；无需适用的字段没有被反复追问。
- 二次元与真人分支使用各自一致的风格描述。
- 真人写实程度落实到动作、环境光、遮挡、材质和参考用途，未以复制首图姿势或全面美化替代用户选择。
- 已实际调用工具、检查并展示返回产物；没有用提示词或汇总冒充图片。
